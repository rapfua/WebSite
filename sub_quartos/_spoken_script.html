Long story short, I am thrilled to be working on a subject that I used to think was too niche to find work in. Also, it seems it can even be useful… shocker! The starting point for my research is Maximilien & Patrick’s “Why the Metric Backbone Preserves Community Structure”. In this paper, they discovered, empirically on datasets such as the MNIST dataset of digits, that spectral clustering applied to the metric backbone is far less sensitive to the number of neighbors chosen when running the spectral clustering algorithm than the original graph and has a similar level of predicting power. In other words, without losing any prediction power, there is one hyperparameter less for which we need to optimize.

My first main objective is to do the same comparison with generated data for which we know the underlying distribution, in marked contrast with the MNIST dataset for instance. The hope is then to prove under certain conditions that the metric backbone is indeed insensitive to the number of neighbors. I will show you one exploratory tool I have developed using quarto to visualize this comparison.

Accessing C++ code from Python

  • In the simulation I will show in two tabs, I started out with 2 dimensional data. To make sure it scaled properly, Patrick asked me to do it in 784 dimensions and compare my results with a known benchmark. I think you see where I am going with this. My python code was SLOWWW. So I asked myself if quarto’s multi-language support is powerful enough to define a function in C++ and call it from Python. Since unlike in the bank, I am allowed to hop from one software to another, I started with what I now: the R programming language’s Rcpp library that makes a bridge between C++ and R. I then found Python’s rpy2 library that makes a bridge between R and Python. I sounds convoluted, but it is actually as simple as this. Note that it is also possible to have a seperate C++ file that is called in the python script, without having to define the C++ function in the python script.
